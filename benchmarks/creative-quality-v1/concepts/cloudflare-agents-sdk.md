# Concept sheet — Cloudflare Agents SDK

## Shared production contract

- Audience: developers building stateful AI agents and technical decision-makers evaluating the runtime.
- Objective: express durable identity and state as a concrete product capability, not vague AI futurism.
- Source pixels: current official documentation, code, logos, and diagrams only.
- Generated imagery: abstract runtime space, topology, depth, and lighting. Never generate fake Cloudflare UI, terminal output, code, or customer logos.
- Required formats: 4:5 primary and 1:1 adaptation.
- Required editable controls: headline, code crop, node count, path routing, channel labels, state layers, CTA, and theme.

## CF-01 — Every agent gets a durable identity

### Argument

An agent is a persistent addressable object with its own identity and state.

### Copy hierarchy

1. **Every agent gets a durable identity.**
2. State, connections, scheduling, and recovery on Cloudflare.
3. `Build and host agents` plus official docs CTA.

### Composition

- One luminous identity core anchors concentric state layers.
- Real API code identifies the `Agent` class and one durable state operation.
- Connections leave and return to the same core, making persistence visible over time.
- Cloudflare orange is used surgically against charcoal and warm white.

### Asset plan

- Official logo or permitted wordmark.
- Verified code excerpt from current documentation.
- Optional documentation crop showing the durable identity language.

### Fidelity and rejection rules

- Code must compile conceptually and remain verbatim from the cited docs.
- Do not claim benchmarked scale, speed, cost, or automatic model intelligence.
- Reject if the visual could advertise any AI platform by changing the logo.

### Scene primitives exposed

`text`, `codeBlock`, `identityCore`, `stateRing`, `path`, `label`, `logo`, `glow`, `safeArea`

## CF-02 — One agent, many channels

### Argument

One durable agent can connect to multiple documented interaction surfaces.

### Copy hierarchy

1. **One agent. Many ways in.**
2. Chat, email, voice, Slack, and webhooks around one durable runtime.
3. `Agents SDK on Cloudflare`

### Composition

- A single central runtime object connects to five labeled channel portals.
- Each portal uses type and a simple abstract symbol; do not use third-party marks unless permitted.
- A subtle orbital time path shows the same agent persisting across sessions.
- High-energy radial composition balanced by a quiet documentation-style footer.

### Asset plan

- Official Cloudflare mark.
- Current docs source verifying each channel label.
- Optional official architecture illustration if its license and accuracy fit.

### Fidelity and rejection rules

- Only list integration surfaces present in the current official documentation.
- Do not imply identical maturity or automatic configuration across channels.
- Reject if it becomes a logo cloud, generic network diagram, or unreadable spoke chart.

### Scene primitives exposed

`text`, `runtimeCore`, `portal`, `path`, `channelLabel`, `timeOrbit`, `logo`, `safeArea`

## CF-03 — State survives the conversation

### Argument

Conversation is transient; the agent's durable state is not.

### Copy hierarchy

1. **State survives the conversation.**
2. Local SQL storage and real-time connections inside each agent.
3. A verified code excerpt that stores or retrieves state.

### Composition

- Conversation fragments pass across the poster and fade.
- A structured state ledger stays fixed beneath them, with one real code block connecting the two.
- The visual language combines editorial code typography with a dimensional data substrate.
- Use depth sparingly; legibility and technical credibility dominate.

### Asset plan

- Verified official code excerpt.
- Official documentation citation.
- Official mark.
- Generated abstract data substrate allowed behind deterministic code and type.

### Fidelity and rejection rules

- Do not present explanatory artwork as a product screenshot.
- Avoid database or security claims not made by the docs.
- Reject if the code is decorative gibberish or if the durability idea is not understandable without reading all body copy.

### Scene primitives exposed

`text`, `messageFragment`, `stateLedger`, `codeBlock`, `connector`, `surface`, `logo`, `safeArea`
